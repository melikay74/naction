# NAction Advisors — one-page site

React + TypeScript front end (Vite) with a small Express API, serving two audiences on one page:

- **Accident victims** enter a zip code, pick which services they need, and get up to 5 partners per
  category with a "Load more" for the rest.
- **Businesses** read the value proposition and submit an application to join the network.

## Running it

```bash
npm install
npm run dev
```

- Site: <http://localhost:5183>
- Privacy policy: <http://localhost:5183/privacy>
- API: <http://localhost:3011> (Vite proxies `/api` to it)

Ports are off the usual 5173/3001 to avoid other dev servers on this machine. Override the API port with
`API_PORT` (the client proxy reads the same variable).

Production — one process serves both the built page and the API:

```bash
npm run build && npm start
```

Other scripts: `npm run typecheck`.

## Photography

Camera originals live in `assets-originals/` (gitignored, never modified). Only optimized copies ship,
generated by:

```bash
cd client && ./scripts/optimize-images.sh
```

That resizes everything in `assets-originals/` to 1200px wide at quality 72 and writes it into
`client/public/`. 1200px covers the largest display size (~500 CSS px) at 2× device pixel ratio.

Add new photos to `assets-originals/`, re-run, done. The script always reads from the originals, so
repeated runs are not lossy.

**This matters more than it sounds.** The originals were 3000–7000px and ~15MB total; optimized they are
871KB. On first view the page now downloads about 600KB, and the three service photos only load when
their tab is opened. On a phone with poor signal — which is exactly the situation this site exists for —
that is the difference between a usable page and a 30-second wait.

The figures set `aspect-ratio` and `height: auto` in CSS while the `<img>` carries `width`/`height`
attributes. Both halves are required: the attributes reserve the right space so nothing shifts as photos
arrive, and `height: auto` stops the height attribute from overriding `aspect-ratio` and distorting the
photo. Measured Cumulative Layout Shift is 0.

## Privacy, cookies, and fonts

**The site currently sets no cookies at all** — no analytics, no advertising, no third-party tracking —
and makes **zero external requests**. Fonts are self-hosted from `client/public/fonts/` (regenerate with
`node scripts/fetch-fonts.mjs public/fonts`), so no visitor IP is disclosed to Google or anyone else.

Because nothing is tracked, the consent banner **deliberately does not render**. Putting a modal in front
of someone who has just been in a collision, to consent to cookies that do not exist, would be pure
friction.

To turn analytics on, set `analyticsId` in [`client/src/config.ts`](client/src/config.ts) to your GA
measurement ID. That one change:

- makes the consent bar appear, with Accept and Decline given equal weight;
- loads the tracking script **only** after an explicit Accept — this is a real gate, not a notice;
- remembers the choice and, on Decline, clears any `_ga*` cookies already set.

With `analyticsId` null the tracking code is tree-shaken out of the production bundle entirely; setting
it brings it back. Verified in both states.

**Never add a tracking script anywhere except [`client/src/lib/analytics.ts`](client/src/lib/analytics.ts)**
— a script added elsewhere bypasses consent and makes the banner a lie.

`/privacy` carries a policy written from what the site actually does. **It is a draft and says so on the
page**; it needs review by counsel, and the retention period and any service providers must be confirmed
before launch. It is self-styled rather than using the design system, so it reads as a plain legal
document.

Two things to raise with a lawyer, neither of which is a coding matter:

- **A privacy policy is required** under California's CalOPPA because the partner application form
  collects names, emails, and phone numbers. That obligation exists now, regardless of company size.
- **California Business & Professions Code § 6155** regulates lawyer referral services. A business
  connecting accident victims with personal injury attorneys may fall under it and require State Bar
  certification.

## Before launch

1. **Replace the partner directory.** `data/partners.json` ships with ~55 *fictional* placeholder
   businesses, each marked `"seed": true` with an `example.com` website. None of them are real. The server
   re-reads the file whenever it changes on disk, so no restart is needed after editing.

2. **Fill in the real contact details.** Everything the site publishes about the business lives in
   [`client/src/config.ts`](client/src/config.ts) — phone, email, website, tagline. The published phone is
   labelled as the partner line (for businesses joining), per the brief.

3. **Add the images.** Drop them in `client/public/` and they replace their labelled placeholder frames
   automatically:
   - `join-qr.png` — QR code pointing at the site's `#apply` anchor.
   - `service-area.png` — California service-area map.
   - Photography: `hero.jpg`, `service-tow.jpg`, `service-repair.jpg`, `service-legal.jpg`.

4. **Configure email.** Applications append to `data/applications.json` and are emailed when SMTP is
   set up — see the email section in [DEPLOY.md](DEPLOY.md). With SMTP unset, the file is still written
   and a warning is logged, so nothing is lost. Email logic lives in
   [`server/src/email.ts`](server/src/email.ts).

## Partner records

```jsonc
{
  "id": "tow-la-001",              // unique
  "category": "tow",               // tow | repair | legal
  "name": "Westside Tow & Recovery",
  "phone": "(213) 555-0142",
  "website": "https://…",          // optional
  "city": "Los Angeles",
  "zips": ["90210", "90211"],      // optional: exact zips served — ranked first
  "regions": ["LA"],               // LA | SD | IE | CENTRAL | BAY | SAC | NORTH
  "statewide": false,              // shown anywhere in CA, as a last resort
  "tier": "gold"                   // optional: "platinum" | "gold" | "silver" — paid membership
}
```

**Matching** runs on proximity bands — an exact `zips` listing beats a `regions` match, which beats a
`statewide` partner. Zip → region mapping lives in [`server/src/regions.ts`](server/src/regions.ts).

**Membership tiers** sit on top of that. Platinum, gold, and silver partners lead their result column
in that order —
but **only if they actually cover the searched area** (a `zips` or `regions` match). A statewide-only
sponsor keeps its badge and stays in normal proximity order, so it can never outrank a partner that truly
serves the caller's zip. Someone stranded after a crash should not be routed past a closer option. Below
the sponsored block, proximity decides and tier only breaks ties inside a band.

**At most 3 partners per tier per category** (27 sponsored slots: platinum, gold, and silver × towing,
repair, legal). The server enforces this on load — extras beyond the third, and any unrecognised tier value, are
logged as a warning and shown untiered rather than crashing the API. Watch the server log after editing
`partners.json`.

The order stays total and stable, so paging with `offset` never repeats or skips a row.

## API

`GET /api/partners?zip=90210&categories=tow,repair,legal&limit=5&offset=0`

One endpoint covers both the initial search (several categories, offset 0) and a "load more" click (one
category, that column's current offset).

```jsonc
{
  "zip": "90210",
  "regionLabel": "the Los Angeles area",
  "results": {
    "tow": { "items": [ /* … */ ], "total": 10, "hasMore": true }
  }
}
```

`POST /api/apply` — validates the application, rejects a filled honeypot field, rate-limits to 5 per hour
per IP, and appends to `data/applications.json` via a temp-file-and-rename write so concurrent
submissions can't clobber each other. Returns `201 {"ok": true, "id": "…"}`.

Both return `400 {"error": "…", "field": "…"}` on bad input; the client shows `error` inline against
`field`.

## Design system

Two stylesheets, with a deliberate split:

- `styles/clarity.css` — the design system: colour, type, and component classes (`.btn`, `.card`,
  `.input`, `.chip`, `.tag`, `.nav`). Reuse these rather than writing parallel ones. White ground, teal
  accent, rounded elevated cards, sentence-case Plus Jakarta Sans, drawn from the carinsurance.com and
  keynest.com references.
- `styles/app.css` — page composition only: section rhythm, grids, and the display typography the
  landing page needs above the system's defaults. Never redefine tokens here.

No component uses inline styles. The two exceptions are `CookieConsent.tsx` and `pages/Privacy.tsx`,
which carry scoped `<style>` blocks so they render consistently without depending on the design system.

Both stylesheets are imported once in `main.tsx`.
